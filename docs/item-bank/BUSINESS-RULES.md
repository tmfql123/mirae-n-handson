# item-bank-php 비즈니스 규칙 후보

> 대상: `legacy/item-bank-php/` · 선행 문서: [ARCHITECTURE.md](ARCHITECTURE.md), [ERD.md](ERD.md)
> 읽은 범위: `search.php` · `register.php` · `units.php` 전문, `db/mariadb/init/01-schema.sql` 전문. `index.php` · `inc/*.php` · `vendor/simplelog/Log.php` 는 SQL 키워드 grep 과 링크 확인만(§3).
> 확신도 — **확실**: 조건문 · SQL 로 확인, 또는 실행으로 확인 / **추정**: 이름 · 주석 · 언어 동작으로 짐작(실행해 보지 않음).
> 실행한 것은 BR-08 의 PHP `(int)` 형변환 확인 하나뿐이다(모듈 Dockerfile 과 같은 `php:7.4-apache` 이미지, PHP 7.4.33). 그 밖의 "결과" 는 모두 코드를 읽고 판단한 것이다.

## 1. 문항 검색 — 공통 · 조건 조합 (`search.php`)

### BR-01 공개 문항만 검색 대상
- **규칙**: 문항의 `status` 가 `'A'` 이면 검색 대상이 되고, 그 외(`R` 검수중 · `D` 삭제 등)이면 검색 결과에서 제외한다.
- **근거**: `search.php:522`, `01-schema.sql:70`
- **근거 코드**:
  ```php
  $from   = " FROM v_item_public";            // search.php:522
  ```
  ```sql
  WHERE i.status = 'A';                       -- 01-schema.sql:70
  ```
- **확신도**: 확실
- **비고**:
  - 뷰의 제외 조건은 `WHERE i.status = 'A'`(`01-schema.sql:70`) 하나뿐이다. 뷰가 `JOIN unit u ON u.id = i.unit_id`(`:69`)로 내부 조인하지만, `item.unit_id` 는 `NOT NULL` 이고 FK `fk_item_unit`(`01-schema.sql:32`)이 있어 이 조인으로 추가로 빠지는 문항은 없다.
    ```sql
    CONSTRAINT fk_item_unit FOREIGN KEY (unit_id) REFERENCES unit (id)   -- 01-schema.sql:32
    ```
  - 매직 값 `'A'`. 상태 코드 의미(A=공개 D=삭제 R=검수중)는 `01-schema.sql:26` 주석만 있음. 같은 규칙이 `units.php:17` 에는 뷰 없이 `i.status = 'A'` 로 직접 구현돼 있다(BR-20) — 두 곳을 함께 바꿔야 한다.

### BR-02 검색 조건은 모두 AND 로 결합
- **규칙**: 키워드 · 단원 · 난이도 · 태그 조건이 여럿 주어지면 모두 AND 로 결합해 모든 조건을 만족하는 문항만 보여 준다.
- **근거**: `search.php:44`, `:98`, `:118`, `:215`, `:218`, `:226`, `:244`
- **근거 코드**:
  ```php
  $where    = " WHERE 1=1";
  $where .= " AND unit_code = ?";
  $where .= " AND EXISTS (SELECT 1 FROM item_tag it JOIN tag t ON t.id = it.tag_id"
  ```
- **확신도**: 확실
- **비고**: OR 조합이나 다중 선택은 없다. 태그도 한 번에 하나만 지정할 수 있다(BR-03).

### BR-03 같은 파라미터가 배열로 오면 첫 값만 사용
- **규칙**: `q` · `unit` · `level` · `tag` · `sort` · `dir` · `page` 가 배열(`tag[]=a&tag[]=b`)로 들어오면 첫 값만 쓰고 나머지는 버린다.
- **근거**: `search.php:55`, `:59`, `:63`, `:67`, `:71`, `:75`, `:79`
- **근거 코드**:
  ```php
  $tag = is_array($params['tag']) ? (string)reset($params['tag']) : (string)$params['tag'];
  ```
- **확신도**: 확실
- **비고**: 경고 없이 조용히 버린다.

### BR-04 키워드는 제목 또는 지문 부분 일치
- **규칙**: 키워드(`q`)를 앞뒤 공백 제거 후 입력하면 제목(`title`) 또는 지문(`stem`)에 키워드가 포함된 문항을 찾는다.
- **근거**: `search.php:85`, `:97-98`
- **근거 코드**:
  ```php
  $like = '%' . $q . '%';
  $where .= " AND (title LIKE ? OR stem LIKE ?)";
  ```
- **확신도**: 확실
- **비고**:
  - 100자를 넘으면 100자로 자르고 경고한다(`search.php:86-88`). 입력칸도 `maxlength="100"`(`:494`).
  - 한 글자면 경고만 하고 검색은 한다(`:91-92`).
  - `%` · `_` 는 이스케이프하지 않아 **와일드카드로 동작**한다. 경고 문구로 이를 알린다(`:94-95`).
  - 대소문자 구분 여부는 DB 콜레이션(`utf8mb4_unicode_ci`, `01-schema.sql:33`)에 따른다 — 추정, 실행 확인 안 함.

### BR-05 단원은 단원 코드 완전 일치
- **규칙**: 단원(`unit`)을 입력하면 앞뒤 공백 제거 후 `unit_code` 와 정확히 같은 문항만 찾는다.
- **근거**: `search.php:109`, `:118-120`
- **근거 코드**:
  ```php
  $where .= " AND unit_code = ?";
  $types .= 's';
  $values[] = $unit;
  ```
- **확신도**: 확실
- **비고**: 형식(`/^[A-Za-z][0-9]{1,2}-[0-9]{1,2}$/`, 예 `M5-1`)이 틀려도 **경고만 하고 그대로 조회**한다(`:111-113`). 등록되지 않은 코드여도 경고 후 조회(`:141-142`) → 0건. 등록 화면은 반대로 없는 단원을 거부한다(BR-15) — 같은 "단원 유효성" 규칙이 두 화면에서 다르게 구현됨.

### BR-06 단원 코드 대소문자
- **규칙**: 단원 코드가 대문자가 아니면 경고를 띄우고 입력값을 바꾸지 않은 채 조회한다.
- **근거**: `search.php:115-117`
- **근거 코드**:
  ```php
  if ($unit !== strtoupper($unit)) {
      $warnings[] = '단원 코드는 대문자로 입력하세요. (입력값 그대로 조회합니다)';
  ```
- **확신도**: 확실(경고 · 무변환) / 추정(실제 매칭 결과)
- **비고**: 경고 문구는 소문자면 못 찾는다는 뉘앙스지만, `unit.code` 와 뷰가 `utf8mb4_unicode_ci`(대소문자 무시) 콜레이션이라 `m5-1` 도 `M5-1` 과 일치할 가능성이 높다. 같은 이유로 `:125` 의 단원 이름 조회도 성공해 "등록되지 않은 단원" 경고는 뜨지 않을 것으로 보인다. **실행 확인 필요.**

### BR-07 난이도 지정 시 해당 난이도만
- **규칙**: 난이도(`level`)가 `1`~`5` 중 한 글자이면 그 난이도와 같은 문항만 찾는다.
- **근거**: `search.php:217-221`
- **근거 코드**:
  ```php
  else if (preg_match('/^[1-5]$/', $level)) {
      $where .= " AND level = ?";
  ```
- **확신도**: 확실

### BR-08 범위 밖 난이도는 정수로 바꿔 그대로 조회
- **규칙**: 난이도가 비어 있지 않고 `1`~`5` 한 글자도 아니면 경고를 띄우고 `(int)` 로 바꾼 값과 같은 문항을 찾는다.
- **근거**: `search.php:223-229`
- **근거 코드**:
  ```php
  $warnings[] = '난이도는 1~5 사이여야 합니다.';
  $where .= " AND level = ?";
  $values[] = (int)$level;
  ```
- **확신도**: 확실(분기는 코드, 형변환 결과는 실행으로 확인)
- **비고**: 주석(`:224`)은 "대개 0건"이라고 하지만, PHP 7.4 의 `(int)` 는 앞쪽 숫자만 읽으므로 **숫자로 시작하는 값은 0 이 아니다**. 아래는 `trim`(`:211`) → `preg_match('/^[1-5]$/')`(`:217`) → `(int)`(`:228`) 순서를 모듈과 같은 이미지(`php:7.4-apache`, PHP 7.4.33, `legacy/item-bank-php/Dockerfile:1`)에서 `php -r` 로 실행한 결과다.

  | 입력 | trim 후 | 1~5 정규식 | `(int)` | 조회 결과 |
  |---|---|---|---|---|
  | `3a` · `3.9` · `03` · ` 03` · `+3` | 같음 / `03` | 불일치 | 3 | **경고 + 난이도 3 문항 조회** |
  | `3 ` | `3` | 일치 | 3 | 경고 없이 난이도 3 (BR-07) |
  | `abc` | `abc` | 불일치 | 0 | 경고 + 0건 |
  | `0` | `0` | 불일치 | 0 | 경고 + 0건 (`'0' == ''` 은 거짓이라 BR-10 으로 가지 않음) |
  | `6` | `6` | 불일치 | 6 | 경고 + `level = 6` |
  | `-1` | `-1` | 불일치 | -1 | 경고 + `level = -1` |
  | `1e1` | `1e1` | 불일치 | 10 | 경고 + `level = 10` (PHP 7.1+ 는 지수 표기를 해석) |

  - `6` · `-1` · `10` 이 0건인지는 데이터에 달려 있다 — `level` 에 CHECK 제약이 없다(`01-schema.sql:25` 주석만).
  - 요약에는 `(int)` 값이 찍힌다(`:229`, 예: `3a` → "난이도 3"). 입력값과 요약이 다르다.
  - "조회 결과" 열은 코드상 흐름이다. DB 에 실제 요청해 본 것은 아니다.

### BR-09 난이도 판정에 느슨한 비교 사용
- **규칙**: 난이도 값이 `''` 와 `==` 로 같으면 "미지정"으로 본다.
- **근거**: `search.php:214`
- **근거 코드**:
  ```php
  if ($level == '') {
  ```
- **확신도**: 확실
- **비고**: `$level` 은 항상 문자열이라(`:63`, `:211`) PHP 7.4 에서 `'' == ''` 외에는 참이 되지 않는다(추정). 이관 시 `===` 로 옮겨도 동작은 같을 것으로 보인다.

### BR-10 난이도 미지정 시 난이도 5 제외 ⚠️
- **규칙**: 난이도를 비우면(`level` 없음 또는 빈 값) `level < 5` 인 문항만 찾는다 — 즉 **난이도 5 문항은 결과에서 빠진다**.
- **근거**: `search.php:213-216`
- **근거 코드**:
  ```php
  // 난이도 값이 비어 있으면 전체 난이도 검색 (1~5 모두 포함)
  if ($level == '') {
      $where .= " AND level < 5";
  ```
- **확신도**: 확실
- **비고**: **주석과 코드 불일치.** 주석은 "1~5 모두 포함", 코드는 1~4 만. 폼의 기본 선택지 라벨도 `'전체'`(`:192`)다. 조건 없이 검색해도(요약 "조건 없이 검색했습니다", `:356`) 난이도 5 는 나오지 않는다. 의도된 정책인지 버그인지는 **미확인** — 이관 시 characterization 스냅샷으로 현행 동작을 먼저 고정할 것. 매직 넘버 `5`.

### BR-11 태그는 이름 완전 일치 · 하나만
- **규칙**: 태그(`tag`)를 입력하면 앞뒤 공백 제거 후 그 이름의 태그가 붙은 문항만 찾는다.
- **근거**: `search.php:235`, `:244-247`
- **근거 코드**:
  ```php
  $where .= " AND EXISTS (SELECT 1 FROM item_tag it JOIN tag t ON t.id = it.tag_id"
          . " WHERE it.item_id = v_item_public.id AND t.name = ?)";
  ```
- **확신도**: 확실
- **비고**: `=` 비교라 `%` · `_` 는 문자 그대로다. 이 경우 "부분 일치를 지원하지 않습니다" 경고(`:237-238`). 50자 초과는 50자로 잘라 경고(`:240-242`, `tag.name VARCHAR(50)` 과 같은 값). 등록되지 않은 태그면 경고 후 그대로 조회 → 0건(`:250-260`). 등록 화면은 모르는 태그를 조용히 버린다(BR-17) — 구현이 다름.

## 2. 문항 검색 — 정렬 · 페이지 (`search.php`)

### BR-12 기본 정렬은 난이도 내림차순, 같으면 ID 오름차순
- **규칙**: 정렬 기준(`sort`)이 비어 있거나 알 수 없는 값이면 `level DESC, id ASC` 로 정렬한다.
- **근거**: `search.php:317-326`
- **근거 코드**:
  ```php
  case '':
      // 기본 정렬: 어려운 문항부터, 같은 난이도면 번호 순
      $orderBy = " ORDER BY level DESC, id ASC";
  ```
- **확신도**: 확실
- **비고**: 알 수 없는 값이면 경고 후 `sort` 를 비운다(`:322-325`). BR-10 때문에 기본 검색의 첫 행은 난이도 4 문항이다.

### BR-13 정렬 기준별 순서와 기본 방향
- **규칙**: 정렬 기준이 `id` · `title` · `unit` · `level` · `created` 이면 아래 순서로 정렬하고, 방향(`dir`)이 없으면 `level` · `created` 는 내림차순, 나머지는 오름차순으로 한다.
- **근거**: `search.php:266-268`, `:276-316`, `:328-331`
- **근거 코드**:
  ```php
  $orderBy = " ORDER BY unit_code ASC, level DESC, id ASC";
  $dir = ($sort === 'level' || $sort === 'created') ? 'desc' : 'asc';
  ```
- **확신도**: 확실
- **비고**:

  | sort | asc | desc | dir 없음 |
  |---|---|---|---|
  | `id` | `id ASC` | `id DESC` | asc |
  | `title` | `title ASC, id ASC` | `title DESC, id ASC` | asc |
  | `unit` | `unit_code ASC, level DESC, id ASC` | `unit_code DESC, level DESC, id ASC` | asc |
  | `level` | `level ASC, id ASC` | `level DESC, id ASC` | desc |
  | `created` | `created_at ASC, id ASC` | `created_at DESC, id ASC` | desc |

  - `sort` · `dir` 는 소문자로 바꿔 비교한다(`:266-267`). `dir` 이 `asc`/`desc` 가 아니면 경고 후 무시(`:268-273`).
  - `unit` 정렬은 방향과 무관하게 2차 키가 항상 `level DESC` 다.
  - `created` 는 SQL 로는 지원되지만 열 머리글 정렬 링크(`:392-397`)에는 없다 — URL 로만 쓸 수 있음.
  - 머리글에서 `level` 은 첫 클릭이 내림차순(`:410-413`), 나머지는 오름차순.

### BR-14 한 페이지 20건, 페이지 번호 1~999
- **규칙**: 페이지 번호가 숫자가 아니거나 1 미만이면 1페이지로, 999 를 넘으면 999페이지로 보정하고, 한 페이지에 20건씩 보여 준다.
- **근거**: `search.php:336-349`, `:523`, `:553`
- **근거 코드**:
  ```php
  if ($page > 999) {
      $page = 999;
  $offset = ($page - 1) * 20;
  ```
- **확신도**: 확실
- **비고**: 페이지 크기 `20` 이 세 곳에 따로 박혀 있다(`:349` OFFSET 계산, `:523` `LIMIT 20`, `:553` `page_size`). 한 곳만 바꾸면 어긋난다. 숫자 아닌 값(`-1` 포함)은 경고 후 1페이지, `0` 은 경고 없이 1페이지(`:337-344`). 총 페이지를 넘는 번호는 보정하지 않는다 → 빈 표가 아니라 `total>0` 이면 헤더만 있는 표가 나올 수 있음(추정, `:657-681`). 결과 0건이면 "검색 결과가 없습니다"(`:657-659`).

## 3. 문항 등록 검증 (`register.php`)

> **수정 · 삭제 기능은 없다.** 모듈의 파일은 `Dockerfile` · `index.php` · `register.php` · `search.php` · `units.php` · `inc/db.php` · `inc/layout.php` · `vendor/simplelog/Log.php` 8개가 전부다(`find legacy/item-bank-php -type f`). 이 8개를 `UPDATE` · `DELETE` 로 grep 하면 `register.php:87` 의 행 잠금 절 `FOR UPDATE` 1건만 나오고, 갱신문(`UPDATE <테이블> SET`) · 삭제문은 0건이다(ERD.md §3). 첫 화면도 검색 · 등록 · 단원 목록 세 화면만 링크한다(`index.php:9-11`). 아래는 등록(POST)에만 해당한다.
> ```php

### BR-15 등록 입력 검증 — 거부 조건
- **규칙**: 제목(앞뒤 공백 제거)이 5자 미만이거나 200자 초과이면, 지문이 비었으면, 단원이 목록에 없으면, 난이도가 `1`~`5` 한 글자가 아니면 등록을 거부하고 오류를 모두 보여 준다.
- **근거**: `register.php:41-44`, `:49-54`, `:56-58`, `:60-68`, `:70-72`, `:83`
- **근거 코드**:
  ```php
  if (mb_strlen($title, 'UTF-8') < 5) {
  if (!preg_match('/^[1-5]$/', $level)) {
  if (empty($errors)) {
  ```
- **확신도**: 확실
- **비고**:
  - 글자 수는 바이트가 아니라 `mb_strlen` 문자 수. 200 은 `item.title VARCHAR(200)`(`01-schema.sql:23`)과 같다. 매직 넘버 `5` · `200`.
  - 주석 "공백 제외 아님, 앞뒤 공백만 제거"(`:48`)는 코드(`trim`, `:41`)와 일치.
  - 지문은 길이 상한이 없다(`stem TEXT`).
  - 단원 유효성은 단원 **ID** 를 DB 목록(`:27`)과 문자열 비교해 판정한다. 검색 화면은 단원 **코드**로, 없어도 조회한다(BR-05).

### BR-16 등록 직후 상태는 검수중(R)
- **규칙**: 검증을 통과해 등록하면 문항 상태를 `'R'` 로 저장한다 — 따라서 등록 직후에는 검색(BR-01) · 단원 목록 문항 수(BR-20)에 나오지 않는다.
- **근거**: `register.php:84`, `:93-94`, `:116`
- **근거 코드**:
  ```php
  "INSERT INTO item (id, unit_id, title, stem, level, status, created_at, updated_at)
   VALUES (?, ?, ?, ?, ?, 'R', NOW(), NOW())"
  ```
- **확신도**: 확실
- **비고**: 스키마 기본값은 `'A'`(`01-schema.sql:26`)인데 코드는 `'R'` 을 명시한다. `R → A` 로 바꾸는 코드는 이 모듈에 없다(검수 주체 미확인). 안내 문구 "검수 완료 후 검색에 노출됩니다"(`:116`).

### BR-18 같은 태그를 두 번 보내면 등록 전체 실패


### BR-19 (참고) 문항 ID 는 현재 최댓값 + 1
- **규칙**: 새 문항 ID 는 트랜잭션 안에서 `MAX(id) + 1`(없으면 1)로 정한다.
- **근거**: `register.php:85-90`
- **근거 코드**:
  ```php
  $res = $conn->query("SELECT COALESCE(MAX(id), 0) + 1 AS next_id FROM item FOR UPDATE");
  ```

- **확신도**: 확실
- **비고**: `item.id` 는 AUTO_INCREMENT 가 아님(`01-schema.sql:21`). `created_at` · `updated_at` 은 DB `NOW()` — 프로젝트 규칙(주입 `Clock`)과 다르므로 이관 시 주의.

## 4. 목록 · 선택지 정렬과 제외 (`units.php` 외)

### BR-20 단원 목록은 학년 → 코드 순, 문항 수는 공개 문항만
- **규칙**: 단원 목록을 보여 줄 때 학년 오름차순 · 코드 오름차순으로 정렬하고, 문항 수에는 `status = 'A'` 문항만 센다.
- **근거**: `units.php:15-19`
- **근거 코드**:
  ```php
  (SELECT COUNT(*) FROM item i WHERE i.unit_id = u.id AND i.status = 'A') AS item_count
    FROM unit u
   ORDER BY u.grade ASC, u.code ASC
  ```
- **확신도**: 확실
- **비고**: 문항이 0개인 단원도 목록에 나온다(서브쿼리 COUNT). 이 수에는 **난이도 5 가 포함**되므로, 같은 단원을 검색 화면에서 난이도 미지정으로 찾으면 건수가 다를 수 있다(BR-10과 불일치).

### BR-21 단원 · 태그 선택지 순서
- **규칙**: 단원 선택지는 학년 → 코드 오름차순, 태그 선택지는 ID 오름차순으로 보여 준다. 검색 폼의 단원 선택지는 학년별 `optgroup` 으로 묶는다.
- **근거**: 단원 `register.php:27`, `search.php:156`, `:452-462` / 태그 `register.php:34`, `search.php:178`
- **근거 코드**:
  ```php
  $res = $conn->query("SELECT code, name, grade FROM unit ORDER BY grade ASC, code ASC");
  $res = $conn->query("SELECT name FROM tag ORDER BY id ASC");
  ```
- **확신도**: 확실
- **비고**: 같은 정렬이 세 곳(`units.php:19`, `register.php:27`, `search.php:156`)에 각각 박혀 있다(현재는 일치). 결과 표의 `tag_names` 도 태그 ID 순 쉼표 구분(`01-schema.sql:64`). 검색 폼은 태그 **이름**을, 등록 폼은 태그 **ID** 를 값으로 쓴다.
