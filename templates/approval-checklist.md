# 승인 체크리스트 v1 · 2회차

오늘 바뀐 점
- 테스트 통과를 "충분한가" 판단에서 신규 메서드 · 엔드포인트 · 예외 분기마다 테스트가 있는지 묻는 예/아니오 항목으로 바꿨다.
- 치명 이슈를 4종(비밀값 노출 · 데이터 손실 · 인증 우회 · SQL 문자열 조립)으로 한정했다.
- 범위 밖 변경은 같은 파일 안의 import 정리만 허용하고, 컨벤션은 반려 3종(계층 규칙 · 빈 catch · System.out)과 경고(네이밍 등)로 나눴다.

AI 가 만든 변경분 · 외주사 PR 을 머지하기 전에 리뷰어가 대조하는 목록이다. 모든 항목은 "예/아니오"로 답한다. 한 기준 안에서 반려 항목이 하나라도 "아니오"면 그 기준은 미충족이다. 네 기준이 **모두** 충족되어야 승인이고, 하나라도 미충족이면 반려다.

## 심각도 정의

- **치명** — 2절의 4종(비밀값 노출 · 데이터 손실 · 인증 우회 · SQL 문자열 조립)에 해당하는 문제. 1건이라도 있으면 반려. 4종 밖의 문제는 치명으로 올리지 않는다.
- **경고** — 네 기준의 반려 항목에는 해당하지 않지만 다음 변경에서 사고가 될 수 있는 문제(네이밍, N+1 쿼리 등). 승인 · 반려에 영향을 주지 않고 이슈 목록에 남긴다.
- **제안** — 더 나은 방법이 있다는 의견. 승인 · 반려에 영향을 주지 않는다. 목록으로만 남긴다.

승인 여부는 네 기준의 충족 여부로만 정한다. 리뷰어가 경고를 이유로 반려하거나, 미충족 기준을 재량으로 승인하지 않는다.

이슈 한 건은 심각도 · `파일:줄번호` · 근거 · 수정 방향 네 항목으로 적는다. 근거 줄번호를 댈 수 없는 지적은 "확인 필요"로 따로 둔다.

## 1. 테스트 통과

- [ ] 변경된 모듈의 테스트를 CLAUDE.md 1절 명령으로 실제 실행했다 — `modern/api` 는 `./gradlew test`, `modern/web` 은 `npm run lint && npm run typecheck && npm test`.
- [ ] 실행 결과에 실패 · 오류가 0건이다.
- [ ] 기존 테스트를 지우거나 건너뛰게(`skip`, `@Disabled`, `.skip`) 바꾼 곳이 없다.
- [ ] 변경분에서 새로 생기거나 동작이 바뀐 public · package-private 메서드마다, 그 메서드를 직접 호출하는 테스트가 변경분 안에 1건 이상 있다(private 메서드는 대상이 아니다).
- [ ] 새 Controller 엔드포인트마다 상태 코드와 응답 필드를 검증하는 테스트가 1건 이상 있다.
- [ ] 새로 만든 예외 분기(404 · 400 · 409)마다 그 분기를 타는 테스트가 1건 이상 있다.
- [ ] 동작을 바꾼 main 클래스마다 `src/test` 의 같은 패키지에 `<클래스>Test.java` 가 있다.
- [ ] 새로 만들거나 바꾼 테스트 클래스에 `@ActiveProfiles("test")` 가 있고, 테스트 메서드마다 한국어 `@DisplayName` 이 있다.

테스트를 실행하지 못했으면(서버 꺼짐, 의존성 미설치) 이 기준은 "확인 필요"로 두며, "확인 필요"인 채로는 승인하지 않는다.

## 2. 치명 이슈 0건

- [ ] **비밀값 노출** — 비밀번호 · 토큰 · API 키 · 접속 계정이 코드 · 설정 · `@Value` 기본값 · 테스트 · 픽스처 · 로그 메시지 어디에도 리터럴로 들어 있지 않다.
- [ ] **데이터 손실** — 요청에 명시되지 않은 삭제 · 덮어쓰기(DELETE · UPDATE · TRUNCATE · DROP, `delete*`, 기존 행을 덮어쓰는 `save`)가 새로 생기지 않았다.
- [ ] **데이터 손실** — 조건(WHERE) 없는 UPDATE · DELETE 가 없다.
- [ ] **인증 우회** — 인증 · 권한 검사를 빼거나 약하게 바꾼 곳이 없다.
- [ ] **인증 우회** — `config/WebConfig` 의 CORS 허용 출처 · 메서드(5173 출처의 GET)가 넓어지지 않았다.
- [ ] **SQL 문자열 조립** — SQL · JPQL · native query 문자열에 변수를 `+` · `String.format` · `concat` 으로 넣는 곳이 없다(파라미터 바인딩 사용).

## 3. 요청 범위 이탈 없음

- [ ] 요청 문장이 한 문장으로 확인되었다(없으면 판정하지 않고 먼저 묻는다).
- [ ] 변경 파일마다 요청 문장으로 설명되는 변경이 1줄 이상 있다.
- [ ] 요청 문장으로 설명되지 않는 변경 줄은 같은 파일 안의 import 추가 · 삭제 · 정렬뿐이다(메서드 추출 · 이름 변경 · 로그 문구 변경 · 포맷 정리는 범위 밖이다).
- [ ] 의존성 추가 · DB 스키마 변경 · 설정 파일 변경이 있다면 요청에 명시돼 있었다.

## 4. 컨벤션 준수

`convention-check` Skill 이 있으면 그 결과를 쓰고, 없으면 팀 `CLAUDE.md` 2 · 3절과 diff 를 직접 대조한다.

반려 항목 — 하나라도 "아니오"면 미충족

- [ ] **계층 규칙** — Controller 파일에 `Repository` import 가 없고, Controller 메서드 반환 타입에 `@Entity` 클래스가 없다.
- [ ] **계층 규칙** — `modern/web` 의 컴포넌트 · 훅에 `fetch(` 가 없고, 테스트 파일과 주석을 빼면 `src/api/client.ts` 밖에 `localhost:8080` 이 없다.
- [ ] **빈 catch** — 본문이 비었거나 주석만 있는 `catch` 가 없다.
- [ ] **System.out** — `System.out` · `printStackTrace` · `console.log` 가 없다.

경고 항목 — "아니오"면 경고로 이슈 목록에 남기고 판정에는 반영하지 않는다

- [ ] **네이밍** — 파일 · 클래스 · 훅 이름이 CLAUDE.md 규칙(`com.example.<도메인>` 패키지, `src/hooks/use<이름>.ts`, `src/components/<PascalCase>.tsx`, `<이름>.test.ts(x)`)을 따른다.
- [ ] 그 밖의 CLAUDE.md 2절 항목(`@Autowired` 없음, 인자 없는 `now()` 없음, Service 의 `@Transactional`, DTO `record`, Controller `try`/`catch` 없음 등)을 지킨다.

## 판정 형식

첫 줄에 `판정: 승인` 또는 `판정: 반려`. 이어서 네 기준의 충족 · 미충족 · 확인 필요 표, 그다음 이슈 목록(심각도 · `파일:줄번호` · 근거 · 수정 방향). 코드는 수정하지 않는다.
