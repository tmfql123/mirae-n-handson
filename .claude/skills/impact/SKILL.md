# 변경 영향도 분석

## 원칙
- 코드를 고치지 않는다. 파일을 만들지도 않는다. 결과는 대화로만 보고한다.
- 모든 항목에 `파일:줄번호` 근거를 단다. 근거를 못 대면 항목으로 올리지 않고 "추적 한계"나 "미확인"으로 남긴다.
- 인용 전에 해당 줄을 다시 열어 원문과 대조한다. 존재하지 않는 함수 · 파일 · 줄을 인용하지 않는다.
- 호출 방향(A 가 B 를 부르는지, 그 반대인지)을 이름으로 짐작하지 않는다. 호출하는 줄을 근거로 댄다.

## 0. 인자 해석
- `$ARGUMENTS` 가 `파일:줄번호` 형태면 그 줄을 감싸는 함수 · 메서드 · 프로시저를 대상으로 삼는다.
- 이름이면 저장소 전체에서 정의를 찾는다. 이름이 여러 곳에 정의돼 있으면(오버로드 · 같은 이름의 다른 클래스 · 복사본) 후보를 `파일:줄` 로 나열하고 어느 것인지 묻는다.
- 인자가 없으면 멈추고 대상을 묻는다.
- `<모듈명>` 은 대상 파일 경로로 정한다(폴더 이름과 다르다).
  | 경로 | `<모듈명>` |
  |---|---|
  | `legacy/item-bank-php/` | `item-bank` |
  | `legacy/assignment-thymeleaf/` | `assignment` |
  | `legacy/grade-mssql/`, `db/mssql/` | `grade` |
  | `modern/api/.../item/` | `item-bank` |
  | `modern/api/.../assignment/` | `assignment` |
  | 그 밖 | 없음 — 규칙 연결 단계는 "해당 문서 없음"으로 적는다 |

## 절차 (순서대로)

### 1. 정의 위치
- 대상의 정의 줄과 끝 줄(`파일:시작-끝`)을 찾고 본문을 끝까지 읽는다.
- 같은 로직의 **복사본**도 찾는다. `legacy/grade-mssql/sql/*.sql` 의 프로시저는 `db/mssql/init/04-procs.sql` 에도 있다 — 둘 다 정의 위치로 적는다.
- 레거시를 이관한 현행 코드(`modern/api`)나 그 반대가 있으면 "같은 규칙의 다른 구현"으로 적는다(수정 범위를 정하는 데 필요하다).

### 2. 호출부 역추적
진입점에 닿을 때까지 한 단계씩 올라간다. 각 단계마다 호출 줄을 근거로 남긴다.
1. 대상 이름으로 Grep 해서 **직접 호출부**를 찾는다. 매칭된 줄을 하나씩 열어 정의 · 주석 · 문자열 · 같은 이름의 다른 대상인지 걸러 낸다.
2. 각 호출부를 감싸는 함수를 새 대상으로 삼아 1을 반복한다.
3. 아래 진입점에 닿으면 멈춘다.
   | 스택 | 진입점 |
   |---|---|
   | PHP | 브라우저가 직접 여는 `*.php` 파일(최상위 코드), 그 파일을 가리키는 `<form action>` · `<a href>` |
   | Spring MVC / Boot | `@GetMapping` · `@PostMapping` · `@RequestMapping` 메서드 → URL. Thymeleaf 템플릿의 `th:action` · `th:href` 로 화면까지 잇는다 |
   | MS-SQL 프로시저 | 프로시저를 부르는 Java 호출부(`{call ...}` · `EXEC ...`) → 그 호출부의 진입점. 다른 프로시저가 `EXEC` 하는 경우도 찾는다 |
   | React | `src/api/client.ts` 함수 → `src/hooks/use*.ts` → `src/components/*.tsx` → 그 컴포넌트를 렌더하는 화면 |
   | 배치 · 스케줄 · 테스트 | `@Scheduled` · `main` · `characterization/tests/` — 화면이 아니어도 진입점으로 적는다 |
4. 경로가 갈라지면 모든 가지를 적는다. 같은 함수에 여러 번 도달하면 한 번만 펼치고 "위와 같음"으로 표시한다.

### 3. 테이블
- 대상 본문(과 대상이 호출하는 DAO · Repository · 프로시저)에서 SQL · JPA 엔티티 · 뷰를 찾아 **읽기 / 쓰기**를 구분한다.
  - 뷰 · 프로시저 · 트리거는 `db/mariadb/init/`, `db/mssql/init/` 정의까지 따라가 실제 원본 테이블을 적는다.
  - `FOR UPDATE` 는 잠금 절이지 쓰기가 아니다. `UPDATE` 로 grep 한 결과를 그대로 쓰지 않는다.
  - JPA 는 `@Table(name=...)` / 엔티티 이름 → 테이블로 옮기고, 변경 감지로 인한 쓰기(`save` 없는 필드 변경)도 쓰기로 본다.
- 각 테이블 이름으로 저장소를 다시 Grep 해서 **같은 테이블을 읽거나 쓰는 다른 함수**를 찾는다(대상 · 대상 호출 경로 위의 함수는 제외). 이 함수들의 진입점은 2단계처럼 한 단계만 올려 화면 · URL 을 적고, 더 깊은 추적이 필요하면 "추가 분석 후보"로 둔다.

### 4. 비즈니스 규칙 연결
- `docs/<모듈명>/BUSINESS-RULES.md` 가 있으면 읽고, 근거 `파일:줄` 이 대상 본문 · 호출 경로 · 3단계 테이블과 겹치는 규칙 ID 를 모은다. 겹침 방식(근거 줄 일치 / 같은 테이블 / 같은 화면)을 함께 적는다.
- 문서의 근거 줄이 현재 코드와 어긋나 있으면(줄 이동 · 내용 변경) 연결은 하되 "문서 줄번호 불일치"로 표시한다.
- "먼저 볼 것" 표에 오른 규칙이 연결되면 출력에서 강조한다.
- 문서가 없으면 "해당 문서 없음"이라고만 적고 규칙을 새로 만들지 않는다.

### 5. 추적 한계 점검
검색으로 찾을 수 없는 호출 경로가 의심되면 근거와 함께 따로 적는다. 특히 확인할 것:
- 이름을 문자열로 만들어 부르는 호출 — PHP `$fn()` · `call_user_func` · 가변 `include`, Java 리플렉션, 문자열로 조립한 SQL · 프로시저 이름
- 프레임워크가 부르는 경로 — 인터페이스 · 상속 구현(호출부는 인터페이스 타입으로만 보임), AOP · 인터셉터 · 이벤트 리스너, Spring 이 주입하는 빈
- 저장소 밖 호출자 — DB 트리거 · Job, 다른 시스템이 직접 여는 URL, 외부에서 실행하는 SQL
- 템플릿 · JS 에서 URL 을 조립하는 경우(`'/items/' + id`), `PATH_ALIASES` 처럼 경로를 바꿔 매핑하는 곳

## 출력 형식

~~~markdown
# 영향도 분석: <대상>

> 대상 정의: `파일:시작-끝` (복사본 · 다른 구현: `파일:줄` …)
> 모듈: <모듈명> · 읽은 범위: <실제로 연 파일과 줄 범위> · 실행한 것: 없음

## 1. 영향받는 화면 · URL
| 화면 / URL | 진입점 근거 | 경로 번호 |
|---|---|---|

## 2. 호출 경로 (진입점 → … → 대상)
- P1: `GET /x` (`파일:줄`) → `A()` (`파일:줄`) → `B()` (`파일:줄`) → **대상**
- P2: …

## 3. 영향받는 테이블
| 테이블 | 대상의 읽기/쓰기 | 근거 | 같은 테이블을 쓰는 다른 함수 (읽기/쓰기 · 근거 · 진입점) |
|---|---|---|---|

## 4. 관련 규칙 ID
| 규칙 ID | 제목 | 겹침 방식 | 규칙 근거 | 비고 |
|---|---|---|---|---|

## 5. 수정 전에 확보할 테스트 케이스
| # | 경로 · 규칙 | 입력 · 전제 데이터 | 기대 결과(현재 동작) | 확보 수단 |
|---|---|---|---|---|

## 6. 추적 한계
| 의심 경로 | 왜 검색으로 못 찾는가 | 근거 `파일:줄` | 확인 방법 |
|---|---|---|---|
~~~

### 테스트 케이스 제안 기준
- 호출 경로 하나에 최소 1개. 연결된 규칙 ID 마다 조건의 경계값(참 · 거짓 · 경계)을 넣는다.
- 같은 테이블을 쓰는 다른 함수가 있으면, 대상 수정 후 그 함수의 결과가 바뀌지 않는지 보는 케이스를 넣는다.
- 기대 결과는 "올바른 동작"이 아니라 **현재 동작**을 적는다. 주석과 코드가 다르면 코드 쪽 동작을 기대값으로 두고 비고에 불일치를 적는다.
- 확보 수단은 저장소에 있는 것으로 제안한다: 레거시 응답은 `characterization/`(기존 스냅숏 · 테스트는 수정하지 않는다 — 없는 케이스는 "추가 제안"으로), `modern/api` 는 같은 패키지의 `<클래스>Test.java`, `modern/web` 은 대상 옆 `*.test.tsx`. 이미 있는 테스트가 덮고 있으면 그 `파일:줄` 을 적는다.

## 하지 말 것
- grep 한 번으로 "호출부 없음" · "다른 사용처 없음"을 단정하지 않는다. 부재 주장은 검색한 패턴 · 범위 · 매칭 줄을 하나씩 확인한 결과와 5단계 점검을 근거로 쓴다.
- 주석 · 이름만 보고 읽기/쓰기나 호출 여부를 정하지 않는다.
- 코드에 없는 영향(“아마 리포트도 바뀔 것”)을 항목으로 올리지 않는다. 의심이면 추적 한계나 추가 분석 후보로 둔다.
- 수정 방법을 제안하거나 코드를 고치지 않는다.
