# 장애 원인 분석 (RCA)

대상은 `incident-logs/$ARGUMENTS/`, 결과는 `docs/rca/$ARGUMENTS.md` 다.
`$ARGUMENTS` 가 비어 있으면 `ls incident-logs/` 결과를 보여 주고 어느 폴더인지 묻는다.

## 절차

1. **수집 범위** — 파일을 통째로 읽지 않는다. `wc -l` · `head` · `tail` 로 파일별 줄 수 · 기록 기간 · 시각 형식 · 타임존부터 표로 정리한다.
   - 타임존이 다르면 KST 변환 규칙을 먼저 적는다. 처리 대상일(`date=`)과 실행 시각처럼 뜻이 다른 시각 필드를 구분한다.
   - `grep -c` · `awk` 로 레벨 · 키워드별 건수와 분 단위 분포를 집계해 이상 구간과 앞뒤 여유 구간을 정한다.
   - 폴더에 없는 다른 시스템의 로그 · 지표는 "추가 수집 대상"으로 적는다. 비밀값이 평문으로 보이면 위치만 기록한다.
2. **타임라인** — 평소 사이클(기준일) 하나와 이상일을 나란히 둔다. 모든 줄에 `파일:줄번호` 를 단다.
   - 이상 줄에는 `[평소: …]` 로 기준일 값을 붙인다. 첫 알림보다 앞선 "평소와 다른 줄"을 따로 뽑는다.
3. **가설** — 계층(코드 · DB/스키마 · 운영/설정 · 인프라 · 측정/집계)에서 2개 이상 세운다. 가설마다 다음을 적는다.
   - 한 문장 가설 / 지지 근거(`파일:줄번호`) / **반증 조건**(이것이 확인되면 틀렸다) / 확인 방법(명령 · 쿼리)
   - 가설 사이의 관계(직접 원인 · 촉발 경로 · 방어선)는 판정과 분리해 적는다.
4. **반증 시도 → 판정**
   - 먼저 로그로 반증을 시도한다. 실행한 명령과 출력을 그대로 기록한다(C1, C2 … 번호).
   - 다음으로 저장소의 코드 · 설정 · 런북을 대조한다. 못 찾으면 "관련 코드를 찾지 못했다"고 쓰고 검색 명령을 남긴다.
   - 가설마다 **유지 / 기각 / 판단 불가(로그 부족)** 를 판정하고, 판단 불가면 필요한 자료를 적는다.
   - 하나를 **채택**하고, 채택하지 않은 가설은 사유와 함께 표로 남긴다(기여 요인 여부 포함).
   - 의심 동작 · 보안 노출처럼 판정과 별개인 것은 따로 모은다.
   - DB 조회가 필요하면 `readonly` 계정만 쓴다(`app` 금지).
5. **리포트 작성** — `docs/rca/$ARGUMENTS.md` 에 다음 순서로 쓴다.
   - **요약**: 무엇이 · 언제(첫 이상 신호 → 확정 → 감지) · 원인 · 확신 수준과 그 이유
   - 수집 범위 · 타임라인 · 가설과 검증(1~4단계 결과)
   - **원인**: 채택 가설과 기여 요인을 인과 순서로
   - **근거 로그 줄**: 원인 문장과 1:1 로 맞춘 `파일:줄번호` + 원문(마스킹 후)
   - **수정안**: 지금 고칠 결함 지점만. 소스가 저장소에 없으면 컴포넌트 · 동작으로 지정한다
   - **재발 방지**: 같은 유형이 다른 곳에서도 생기지 않게 하는 구조적 장치
   - **모니터링 항목**: 지표 · 임계값 · 이번 로그 기준 발화 시각 · 실제 감지 대비 앞당긴 시간
   - **확인하지 못한 것**: 로그가 없어 판단하지 못한 것 + 다음을 위해 남겨야 할 로그
6. **마스킹** — 리포트를 저장하기 전에 [masking-rules.md](masking-rules.md) 의 규칙을 적용한다.
   - 리포트 끝에 `마스킹 적용: IP n건 · 이메일 n건 · 학생 식별자 n건 · 토큰 n건 · 비밀번호 n건` 한 줄을 남긴다.

## 하지 말 것

- 로그에 없는 줄을 인용하지 않는다. 인용 전에 `sed -n '<줄>p'` 로 원문을 확인한다.
- 가장 많이 나온 오류를 곧바로 원인이라고 부르지 않는다. 기준일에도 같은 빈도면 기저 소음으로 분류한다.
- 원본 로그(`incident-logs/`)와 소스 코드를 수정하지 않는다. 수정안은 리포트에만 쓴다.
- 마스킹 대응표(원본 값 ↔ 별칭)를 파일로 남기지 않는다.
- 마스킹 전 원본을 임시 폴더에 복사해 두지 않는다.
